### 固件

#### bootloader + kernel + rootfs

| 组成部分     | 作用                                                       | 是否通常在固件中           |
| ------------ | ---------------------------------------------------------- | -------------------------- |
| 🔹 Bootloader | 启动加载器，负责最初的引导加载（如 U-Boot、Barebox）       | ✅ 经常包括（有时压缩打包） |
| 🔹 Kernel     | Linux 内核，负责硬件驱动、系统调用等                       | ✅ 通常包含                 |
| 🔹 Rootfs     | 根文件系统，包含 `/bin`, `/lib`, `/etc` 等目录和可执行文件 | ✅ 一定包含                 |

* 把设备的整个根目录打包，无法获取完整的固件
  * 打包的是**运行时的 rootfs**，通常缺少 Bootloader 内核镜像 未挂载的分区内容 设备树（dtb）,有些设备采用了只读 rootfs（如 squashfs），你实际获取的是**挂载后的视图**，原始固件镜像中的压缩结构丢失。
  * qemu-user-static + binfmt_misc +chroot 可以模拟部分应用，无法进行qemu-system
* 如何判断固件中是否包含 Bootloader 和内核映像

###### 直接打包

```shell
# 直接提取整个根目录，可以排除一些目录防止打包和解压过程中出现问题
tar -czvf /tmp/rootfs.tar.gz --exclude=/proc --exclude=/sys / 
tar -xzvf rootfs.tar.gz
```

###### rsync

首先得上传工具到目标设备；rsync支持增量推送

**服务器起rsync，设备推送**

```txt
# 全局配置
uid = root
gid = root
use chroot = no
max connections = 10
log file = /var/log/rsyncd.log
pid file = /var/run/rsyncd.pid

# 定义一个共享模块名，例如 fireware
[fireware]
    path = /home/kali/fireware/GDS3726
    comment = GDS3726 firmware sync dir
    read only = no
    list = yes
    auth users = kali
    secrets file = /etc/rsyncd.secrets

```

```shell
# 服务端起
sudo sh -c 'echo "kali:123456" > /etc/rsyncd.secrets'
sudo chmod 600 /etc/rsyncd.secrets
sudo rsync --daemon --config=/etc/rsyncd.conf
```

```shell
# 设备端推送
./rsync-arm -avzP --exclude={"/proc/*","/sys/*","/dev/*"} / rsync://kali@192.1
68.108.20/fireware/
```

**设备端通过ssh直接推送**

```shell
# /usr/bin/dbclient是ssh客户端
./rsync-arm -avzP -e "/usr/sbin/dbclient -p 22" / root@192.168.108.20:/home/kali/fireware/test/
```
